# خطة فحص نظام 2A

خطة عملية للتأكد من عمل كل جزء من النظام بعد التحديثات الأخيرة (الإدارة الجماعية
للأصناف، سعر الجملة، قالب الفاتورة، وإصلاح ازدواج خصم الدفعات).

> رتّب الفحص كما هو مرتّب: قاعدة البيانات أولاً، ثم الفحص الآلي، ثم الواجهة.
> أي بند يفشل — سجّله وتوقّف عنده قبل الانتقال لما بعده، لأن أغلب الأجزاء
> تعتمد على ما قبلها.

## 0) قبل البدء

| الخطوة              | الأمر                                    | المتوقع                        |
| ------------------- | ---------------------------------------- | ------------------------------ |
| تثبيت الحزم         | `bun install`                            | بلا أخطاء                      |
| فحص الأنواع         | `bunx tsc --noEmit`                      | بلا أخطاء في ملفات المشروع     |
| فحص النمط           | `bunx eslint src scripts`                | 0 errors (تحذيرات ui/ مقبولة)  |
| الفحص الآلي السريع  | `bun scripts/smoke.tsx`                  | ✅ كل الفحوصات نجحت            |

والتواريخ المحلية وتنسيق الفاتورة ورسائل الأخطاء، ويصيّر مكوّني الفاتورة
والشبكة للتأكد من عدم انهيارهما. شغّله بعد أي تعديل على `src/lib` أو المكوّنين.

## 1) الهجرات (خطوة إلزامية)

طبّق ملفات `supabase/migrations` المضافة حديثاً بالترتيب:

1. `20260814090000_c4d81e37_parts_wholesale_price.sql` — عمود `wholesale_price`.
2. `20260814120000_e7a3c15b_payment_double_count.sql` — إصلاح مشغّل الدفعات
   وإعادة احتساب أرصدة العملاء والموردين.

**تحقّق بعد التطبيق** (SQL Editor في Supabase):

```sql
-- (أ) العمود موجود
select column_name from information_schema.columns
where table_name = 'parts' and column_name = 'wholesale_price';

-- (ب) لا يوجد أي عميل رصيده مخالف لمصدره (يجب أن ترجع 0 صف)
with due as (
  select customer_id, sum(total - discount + coalesce(tax_amount,0) - paid) d
  from sales where customer_id is not null group by customer_id
), oa as (
  select p.customer_id, sum(p.amount) a from payments p
  left join sales s on s.id = p.sale_id
  where p.direction='in' and p.customer_id is not null
    and (p.sale_id is null or s.customer_id is distinct from p.customer_id)
  group by p.customer_id
)
select c.id, c.name, c.balance, coalesce(due.d,0) - coalesce(oa.a,0) as expected
from customers c
left join due on due.customer_id = c.id
left join oa on oa.customer_id = c.id
where c.balance is distinct from coalesce(due.d,0) - coalesce(oa.a,0);
```

## 2) الاختبار المحاسبي الحرج (ازدواج الدفعات)

هذا هو الخلل الأهم الذي أُصلح — اختبره قبل أي شيء آخر:

1. أنشئ عميلاً جديداً «عميل اختبار».
2. من **بيع سريع**: فاتورة بصنف سعره 1000، العميل = عميل اختبار، المدفوع = 0،
   ثم احفظ.
3. في صفحة العميل: **الرصيد = 1000**.
4. من الفاتورة اضغط **تحصيل** وسجّل 400.
5. تحقّق: رصيد العميل **600** (وليس 200 كما كان قبل الإصلاح)، والمتبقي في
   الفاتورة **600**، والمدفوع **400**.
6. افتح **كشف حساب العميل**: مجموع «الرصيد» في آخر سطر = 600 = الرصيد المعروض
   في أعلى الصفحة. **تطابق الرقمين هو معيار النجاح.**
7. سجّل دفعة ثانية 600 → الرصيد 0 والفاتورة مسدّدة بالكامل.
8. كرّر نفس السيناريو مع **مورّد + فاتورة شراء + سداد**.

## 3) الأصناف والإدارة الجماعية

### 3-1 صفحة قطع الغيار `/parts`

- [ ] القائمة تعرض: الاسم، الفئة، نوع السيارة، التكلفة (للمدير)، **القطاعي**، **الجملة**، الكمية.
- [ ] «صنف جديد» يحفظ الأسعار الثلاثة، والكود يُولَّد تلقائياً.
- [ ] تعديل صنف يحتفظ بسعر الجملة.
- [ ] حذف صنف مرتبط بفاتورة → رسالة عربية واضحة («مرتبط بفواتير») لا رسالة قاعدة بيانات.
- [ ] البائع (غير المدير) لا يرى أزرار الإضافة/التعديل/الحذف ولا زر «إدارة جماعية».

### 3-2 الإدارة الجماعية `/parts/bulk`

**تبويب «إضافة أصناف»**

- [ ] 10 صفوف فارغة عند الفتح، و«F4» يضيف 10 أخرى.
- [ ] الكتابة في آخر صف ثم `Enter` تُنشئ صفاً جديداً وتنتقل إليه.
- [ ] صف بلا اسم لكن بأرقام → يُعلَّم بالأحمر ويمنع الحفظ برسالة واضحة.
- [ ] حفظ 20 صفاً دفعة واحدة → «تم الحفظ — 20 إضافة»، وتظهر كلها في `/parts` بأكواد مختلفة.
- [ ] إدخال الأرقام العربية (٢٥٠) يُحفظ 250.

**تبويب «تعديل الأصناف»**

- [ ] البحث يصفّي، وترقيم الصفحات يعمل مع تغيير عدد الصفوف/صفحة.
- [ ] تعديل خلية → تلوّن الخلية والصف وظهور «تعديل غير محفوظ» في العدّاد.
- [ ] `Esc` داخل الخلية يعيد قيمتها الأصلية.
- [ ] «تراجع» يعيد كل التعديلات غير المحفوظة.
- [ ] حذف صف يعلّمه بالأحمر مشطوباً، وزر الاستعادة يتراجع عنه.
- [ ] الحفظ ينفّذ التعديل والحذف معاً ويعرض ملخصاً، ثم تختفي علامات التعديل.
- [ ] تعديل صنفين في صفحتين مختلفتين ثم الحفظ → يُحفظ الاثنان.

**التنقل بالكيبورد** (جرّب كل واحد)

| المفتاح                 | المتوقع                                     |
| ----------------------- | ------------------------------------------- |
| `↑ ↓`                   | نفس العمود، صف لأعلى/لأسفل                  |
| `← →`                   | العمود التالي/السابق (يحترم اتجاه RTL)      |
| `Enter` / `Shift+Enter` | لأسفل / لأعلى                               |
| `Tab` / `Shift+Tab`     | الخلية التالية/السابقة مع الالتفاف بين الصفوف |
| `Home` / `End`          | أول/آخر عمود — ومع `Ctrl` أول/آخر صف        |
| `PageUp` / `PageDown`   | قفزة 10 صفوف                                |
| `Ctrl+D`                | نسخ قيمة الخلية الأعلى                      |
| `Ctrl+Shift+D`          | تعبئة القيمة لكل الصفوف أسفلها              |
| `Ctrl+Space`            | تحديد/إلغاء تحديد الصف                      |
| `Alt+Delete`            | حذف الصف                                    |
| `F2` / `F8` / `F9`      | بحث / نافذة الأسعار / حفظ                   |
| `Ctrl+S`                | حفظ **مرة واحدة** (لا حفظ مزدوج)            |

- [ ] السهم لأسفل في آخر صف بالصفحة ينتقل لأول صف بالصفحة التالية (والعكس).
- [ ] رأس الجدول يبقى ظاهراً أثناء التمرير داخل الشبكة.

### 3-3 تعديل الأسعار الجماعي

## 4) نقطة البيع `/sales/new`

- [ ] البحث بالكود والاسم يعمل، والإضافة بالضغط على الصنف.
- [ ] مفتاح **قطاعي/جملة** (أو `F3`) يبدّل الأسعار: السطور التي لم تُعدَّل يدوياً
      يتغيّر سعرها، والسطر المعدّل يدوياً **يبقى كما هو**.
- [ ] صنف بلا سعر جملة يبقى على سعره القطاعي في وضع الجملة.
- [ ] شبكة الأصناف تعرض سعر الوضع الحالي.
- [ ] الكمية أكبر من المتاح → رسالة رفض، ولا تُحفظ الفاتورة.
- [ ] بيع نفس الصنف من جهازين: الحفظ الثاني يرفض إن نفد المخزون (يُعاد فحص
      المخزون لحظة الحفظ لا من القائمة المخزّنة).
- [ ] الاختصارات: `F2` بحث، `F4` عميل، `F6` حساب، `F7` طريقة الدفع، `F8` تعليق،
      `F9` حفظ.
- [ ] تعليق فاتورة ثم استعادتها يحفظ العميل والخصم والملاحظات **ووضع السعر**.
- [ ] الخصم يحترم سقف صلاحية البائع من الإعدادات.
- [ ] بعد الحفظ: تنقص الكمية من المخزون ويُفتح عرض الفاتورة.

## 5) الفاتورة والطباعة

- [ ] رأس الفاتورة: الشعار على الجانبين (عند تفعيله)، العنوان، اسم المتجر، `TEL`.
- [ ] سطر التاريخ / رقم الفاتورة / اسم العميل بخط منقّط وبلا التفاف.
- [ ] الجدول: `م · الصنف · الكود · السعر (وحدة) · الكمية · الإجمالي`.
- [ ] فاتورة بصنفين على A4 تُكمل الصفوف الفارغة حتى العدد المضبوط في الإعدادات.
- [ ] صندوقا «بيانات الدفع» و«الإجماليات» أسفل الجدول + خانتا التوقيع + التذييل.
- [ ] `معاينة الطباعة` على **A4**: بلا قوائم جانبية أو أزرار، حدود واضحة، صفحة واحدة.
- [ ] **حراري 80mm**: الأعمدة تُختصر، تختفي الصفوف الفارغة وعمود الكود والشعار الثاني.
- [ ] **حراري 58mm**: يبقى مقروءاً بلا قصّ أفقي.
- [ ] تغيير المقاس من شريط الفاتورة يغيّر **شكل المستند على الشاشة** فوراً.
- [ ] «عدد نسخ الطباعة = 2» في الإعدادات → نسختان، كل واحدة بصفحة.
- [ ] الخروج من الفاتورة إلى صفحة أخرى ثم الطباعة لا يورث مقاس الحراري.
- [ ] زر واتساب يفتح الرسالة بالقالب المضبوط.

## 10) حالات حدّية يُنصح بتجربتها

- [ ] فاتورة بلا عميل (نقدي) مدفوعة بالكامل → لا تؤثر على أي رصيد.
- [ ] فاتورة بخصم يساوي الإجمالي → المستحق صفر بلا أرقام سالبة.
- [ ] دفعة أكبر من المستحق → يظهر «رصيد فائض» للعميل بعلامة خضراء.
- [ ] صنف بكمية عشرية (0.5) في البيع والشراء.
- [ ] اسم صنف طويل جداً في الفاتورة الحرارية → يلتف بلا كسر الجدول.
- [ ] 200 صنف في شبكة الإدارة الجماعية → الكتابة تبقى سلسة.
- [ ] قطع الإنترنت أثناء الحفظ → رسالة خطأ واضحة وعدم فقد ما كُتب في الشبكة.
