## نظرة عامة

تنفيذ 4 تحسينات على النظام:

1. **تحسين طباعة الفواتير (A4 + حراري 80/58)**
2. **تعديل الفواتير المحفوظة (جزئي)**
3. **رصيد فائض للعملاء/الموردين**
4. **خصائص طرق الدفع**

---

## 1) طباعة الفواتير — A4 / حراري 80mm / حراري 58mm

- إضافة زر اختيار المقاس داخل صفحة الفاتورة (`sales/$id.tsx` و `purchases.$id.tsx`) — 3 أزرار (A4 / 80mm / 58mm) قبل الطباعة، يطبّق `body.print-format-*` مؤقتاً.
- ضبط `@page` في `styles.css`:
  - A4: `size: A4; margin: 12mm` — عرض كامل، ألوان هادئة، جدول واضح.
  - Thermal 80: `size: 80mm auto; margin: 3mm` — إخفاء الشعار الجانبي، شعار صغير فوق، نص مضغوط، بدون حدود جدول.
  - Thermal 58: `size: 58mm auto; margin: 2mm` — إخفاء أعمدة السعر المفرد، خط أصغر.
- إصلاح خلل الحدود المتقطعة الحالية في الوضع الحراري (`border-bottom: dashed` يبدو مشوشاً في بعض المتصفحات → استبداله بخط `solid` رفيع).
- إضافة صف «رقم العملية» و«الحساب» بشكل مرئي في القالبين الحراريين (حالياً `hide-on-thermal` يخفي الملاحظات فقط).

## 2) تعديل الفواتير — تعديل جزئي

نافذة تعديل من صفحة الفاتورة تسمح بتغيير:

- **الخصم** (يعدّل `sales.discount`).
- **طريقة الدفع** (`payment_method`) + **الحساب** (`account_name`) + **رقم العملية** (يُعاد ترميزه في `notes`).
- **الملاحظات النصية**.
- **المدفوع** (`sales.paid`) — عند تغييره يتم إعادة حساب رصيد العميل تلقائياً عبر trigger الموجود `apply_sale_balance`.

لن يتم تعديل الأصناف/الكميات/الأسعار في هذه المرحلة (يحافظ على تكامل المخزون). نفس النهج للفواتير الشراء (`purchases.$id.tsx`).

مكوّن جديد: `EditInvoiceDialog.tsx` — يستخدم `supabase.update`، ويُنشّط عبر زر «تعديل» بجوار «طباعة».

## 3) رصيد فائض للعملاء/الموردين

- `PaymentDialog` يسمح حالياً بمبلغ يتجاوز المستحق → عند الحفظ، المشغل الحالي `apply_payment` يُنقص الرصيد بالكامل، فيصبح الرصيد سالباً (فائض/دائن). ✅ المنطق يدعم ذلك.
- تحسين العرض:
  - في `customers.$id.tsx` / `suppliers.$id.tsx`: عندما `balance < 0` تُظهر شارة «رصيد دائن (فائض)» بلون أخضر مع القيمة المطلقة.
  - في `PaymentDialog`: عرض «سيصبح الرصيد بعد الحفظ: X (دائن/مدين)» قبل الحفظ.
- إضافة زر «إيداع فائض» في صفحة العميل/المورد يفتح `PaymentDialog` بدون فاتورة — لتسجيل دفعة مقدّمة صريحة.
- في صفحة الفاتورة: عند وجود رصيد دائن للعميل، يظهر تنبيه «للعميل رصيد فائض: X» فوق زر التحصيل.

## 4) خصائص طرق الدفع

توسيع الإعدادات (`src/lib/settings.ts`) وشاشة الإعدادات (`settings.tsx`) بقسم جديد **«طرق الدفع»**:

لكل طريقة (نقدي / بنكي):

- **مفعّلة** (checkbox) — إخفاء الطريقة إن عُطلت.
- **الحساب الافتراضي** (dropdown من `accounts`).
- **يتطلب رقم عملية** (checkbox) — إذا مفعّل ولم يُدخل الرقم عند البيع → منع الحفظ.
- **الطريقة الافتراضية** (radio عام).

الحقول تُخزّن في `settings.paymentMethods: Record<"cash"|"bank", { enabled, defaultAccountId, requireRef }>` + `settings.defaultMethod`.

تُطبّق في POS (`sales/new.tsx`) و `PaymentDialog`:

- ملء الحساب تلقائياً حسب الطريقة.
- إظهار حقل رقم العملية إذا `requireRef` أو الطريقة = بنكي.
- إخفاء الأزرار المعطّلة.

## تفاصيل تقنية

- **بدون تغييرات قاعدة بيانات**: كل الأعمدة مطلوبة (`discount`, `paid`, `payment_method`, `account_name`, `notes`) موجودة، والمشغّلات تُعيد حساب الأرصدة تلقائياً عند `UPDATE`.
- **ملفات ستُعدّل**:
  - `src/styles.css` — قواعد `@media print` لثلاث مقاسات.
  - `src/lib/settings.ts` — إضافة `paymentMethods` + `defaultMethod`.
  - `src/routes/_authenticated/settings.tsx` — قسم طرق الدفع.
  - `src/routes/_authenticated/sales/$id.tsx` + `purchases.$id.tsx` — اختيار المقاس + زر تعديل.
  - `src/routes/_authenticated/customers.$id.tsx` + `suppliers.$id.tsx` — عرض الفائض + إيداع مقدم.
  - `src/components/PaymentDialog.tsx` — احترام خصائص الطرق + معاينة الرصيد الجديد.
  - `src/routes/_authenticated/sales/new.tsx` — احترام الخصائص الجديدة.
- **ملفات جديدة**:
  - `src/components/EditInvoiceDialog.tsx`
  - `src/components/PrintFormatPicker.tsx` (زر مصغّر داخل الفاتورة).

## المخاطر

- تعديل `paid` عبر UI مباشرة يعتمد على المشغّل `apply_sale_balance` لتحديث `customers.balance` — تم التحقق منه في الدوال الموجودة.
- الطباعة الحرارية تعتمد على دعم المتصفح لـ `@page size`؛ Chrome/Edge يدعمانه، Firefox يتجاهل الحجم لكن التنسيق يعمل.
